# 研究总览

## 1. 目标

AI-purge 建立从研究假设、测试样本、变异生成、受控执行、结果判定到防御修复和回归测试的闭环。

核心交付物：
1. 可追溯的提示词与测试样本目录。
2. 有来源、有边界、有适用条件的方法注册表。
3. 可插拔、可复现、受约束的变异引擎。
4. 面向 Agent 工具链的安全测试套件。
5. 跨模型统一评估协议和机器可读报告。
6. 上游实现、许可证、版本和借鉴关系映射。

## 2. 研究边界

允许：对自有模型、本地模型、测试租户或明确授权服务进行评估；使用无害 canary 验证指令优先级、上下文隔离和策略遵循；在沙箱模拟工具副作用；研究变异算法覆盖率、稳定性和成本；评估输入分区、来源标记、工具权限和人工确认等防御。

不作为目标：规避第三方服务安全策略并将其作为能力交付；窃取真实凭据、会话令牌或私有数据；对真实账户执行未授权操作；宣称某个提示词对所有模型或版本有效。

## 3. 统一架构

```

      |

      |

      |

```

## 4. 模块职责

| 模块 | 输入 | 输出 | 控制 |
|---|---|---|---|
| Source Registry | 仓库、论文、文档 | 来源记录 | 许可证、版本 |
| Prompt Catalog | 样本和元数据 | 标准化样本 | 风险标签、脱敏 |
| Method Registry | 方法描述 | 方法卡片 | 适用条件、局限 |
| Mutator | 样本、算子配置 | 变异样本 | 预算、深度 |
| Orchestrator | 测试计划 | 执行记录 | 并发、超时、隔离 |
| Adapter | 标准请求 | 模型响应 | 凭据隔离、目标白名单 |
| Evaluator | 请求、响应、工具轨迹 | 判定与证据 | 人工复核 |
| Reporter | 评估结果 | JSON/Markdown | 可复现配置 |

## 5. 标准流程

1. 定义待验证的安全属性。
2. 指定模型、版本、工具、数据集、授权范围和时间窗口。
3. 使用合成数据与 canary 准备样本。
4. 设定算子、最大深度、样本预算和随机种子。
5. 固定模型参数并执行，记录脱敏轨迹。
6. 按预先声明的成功条件判定。
7. 区分模型输出、工具副作用和评估器推断。
8. 记录防御版本并执行回归。

## 6. 研究原则

可追溯、可复现、最小权限、证据优先、防御闭环、跨模型谨慎。每项结论均应注明模型版本、系统配置、工具权限和评估器版本。
