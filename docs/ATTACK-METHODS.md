# 对抗方法注册表

## 1. 记录原则

方法条目描述研究思路、适用条件、观察指标和局限，不等同于可直接执行的攻击脚本。每种方法都应有防御验证目标，并且只在授权环境内测试。

## 2. 方法分类

### 指令与上下文边界
- 指令冲突测试：构造无害冲突，观察优先级是否稳定。
- 角色边界测试：检查用户内容、引用文本和文档是否造成权限混淆。
- 上下文重构测试：改变消息分段和上下文组织，验证安全语义。
- 多轮状态测试：检查策略是否随上下文增长而漂移。

### 表示与格式鲁棒性
- 大小写、空白、标点和换行归一化。
- Unicode 规范化差异。
- Markdown、JSON、XML、代码块和引用块边界。
- 多语言表达与翻译一致性。
- 长上下文截断、摘要和重排后的语义保持。

### 自动化对抗研究算法

| 方法 | 研究重点 | 工程注意事项 |
|---|---|---|
| GPTFuzz | 模板变异与反馈循环 | 限制预算并固定评估器 |
| ReNeLLM | 重写与场景变换 | 防止语义漂移 |
| PAIR | 迭代式候选搜索 | 记录状态、成本和停止条件 |
| TAP | 树状搜索与候选筛选 | 限制分支因子和深度 |
| AutoDAN | 自动化候选生成研究 | 仅作受控研究，不交付生产绕过配方 |
| GCG | 离散优化方向研究 | 明确模型访问条件和实验边界 |
| ICA | 上下文示例影响 | 区分示例学习与权限提升 |
| DeepInception | 角色/场景结构影响 | 使用无害目标 |
| Cipher / CodeChameleon | 编码表示鲁棒性 | 测试解码边界与策略一致性 |

## 3. 方法卡片字段

method_id、name、family、paper_or_source、hypothesis、required_access、test_surface、safe_fixture、metrics、limitations、defense_mapping、license。

## 4. 执行约束

- 只对登记目标执行。
- 只使用无害 canary 和模拟副作用。
- 限制样本数、并发、token 和时间。
- 工具调用执行 allowlist 与参数校验。
- 真实外部副作用必须单独授权并由人工确认。
- 结果保留证据摘要，不能只记录成功或失败。

## 5. 结果解释

单次命中不代表普遍有效；单次拒绝也不代表系统安全。结论应标注模型版本、系统配置、温度、上下文长度、工具权限和评估器版本。
